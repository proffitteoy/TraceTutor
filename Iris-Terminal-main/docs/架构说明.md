# 架构说明

更新日期：2026-07-27

## 1. 总体定位

`鸢尾花终端` 当前是一个本地优先的单体 Web 应用：

- 前端：Next.js 14 App Router
- 服务端：Next.js Route Handlers
- 数据库：Prisma + PostgreSQL
- 文件存储：本地文件系统 `storage/`
- 模型接入：OpenAI / Azure OpenAI / Anthropic / Gemini / DeepSeek 等

它不是完整复刻上游通用 Chat UI 的所有实体能力，而是保留本地部署场景里已经打通的主链路，并对未落地能力做显式边界控制。

## 2. 分层

### UI 层

- `app/[locale]/*`：页面布局、路由入口
- `components/chat-tree/*`：React Flow 卡片画布、节点、连线、选区 Ask
- `components/chat/*`：复用的单卡完整对话、消息发送和模型交互
- `components/*`：侧边栏、设置、工具组件
- `context/context.tsx`：全局 UI 状态容器

### 数据访问层

- `db/*`：前端对数据的访问入口
- 约束：
  - 已落地能力：调用真实 `/api/local/*` 接口
  - 未落地能力：显式抛出 `UnsupportedLocalFeatureError`

### 服务逻辑层

- `lib/local-bootstrap.ts`：本地用户 / Profile / 默认工作区引导
- `lib/retrieval/processing/*`：文件解析与切片
- `lib/server/*`：服务端聊天与配置辅助逻辑
- `lib/summaries/*`：总结格式、关键词提取

### 持久化层

- `prisma/schema.prisma`：当前本地模式实际落地的数据库模型
- `storage/`：文件二进制内容与图片资源

## 3. 当前真实数据流

### 3.1 启动与本地引导

1. 页面进入工作区布局
2. `ensureLocalBootstrap()` 自动创建或更新：
   - 固定本地用户
   - 本地 Profile
   - 默认工作区
3. `GET /api/local/startup` 聚合返回 Profile、工作区、根聊天和环境 Key 可用性
4. 工作区先显示聊天主界面；文件、远程模型目录和摘要关键词在首屏后按需加载

### 3.2 聊天链路

1. 侧栏打开根聊天，详情页按根聊天 ID 加载 `ChatTree`
2. 画布只展开当前活动卡片，活动卡复用原 `ChatUI`
3. UI 发送聊天请求到 `app/api/chat/*`
4. 消息写入当前卡片对应的 `chats` / `messages`
5. 若触发总结，再由总结相关接口写入 `chat_summaries`

### 3.3 卡片分支链路

1. 用户在单条助手消息内原生选择文本
2. 右键 `Ask` 保存来源消息 ID、引用快照和渲染文本偏移
3. 服务端事务创建深入子卡片；创建时不调用模型
4. 新卡片固定展示引用并聚焦输入框，用户发送后才进入原聊天模型链路
5. 发散卡只携带来源标题和精简摘要；历史分支复制分支点以前的消息
6. 模型上下文按“分支来源与祖先路径 → 当前卡片历史”组合，并继续服从原上下文长度预算

卡片关系保存在 `chats.card_relation`，树归属保存在 `chats.tree_id`。`source_quote` 是独立快照；来源消息删除后引用仍可阅读，但 `source_message_id` 会置空。

### 3.4 文件链路

1. 上传文件到 `app/api/local/files`
2. 文件原文写入 `storage/files/*`
3. 元数据写入 `files`
4. 切片写入 `file_items`
5. 向量按能力写入 `openai_embedding` 或 `local_embedding`

文件列表 `GET` 不加载解析器。DOCX/PDF/Excel 解析器、OpenAI SDK 与本地 Transformers
只在上传和对应向量化分支中动态加载；通用文本切片使用仓库内轻量实现，不依赖完整 Agent 框架。

### 3.5 记忆检索链路

1. `app/api/memory/retrieve` 接收用户输入
2. 优先尝试 OpenAI / Azure Embedding
3. 若失败则降级到本地 Embedding
4. 若仍无结果则降级到词法匹配

## 4. 目录职责

### `app/`

- 页面与 API 路由
- `app/api/local/*` 是本地模式下最重要的真实数据接口

### `db/`

- 只能承担“请求编排与 I/O 适配”职责
- 不允许再放 `null/[]/true` 伪实现掩盖能力缺失

### `lib/`

- 放可复用逻辑
- 不把页面状态管理、数据库请求、存储 I/O 混进 React 组件

### `types/`

- 当前存在“类型面大于本地实现面”的历史遗留问题
- `types/database.ts` 覆盖的实体多于 `prisma/schema.prisma`
- 新增或启用实体能力时，要同时校验这两套定义是否一致

## 5. 当前架构红线

- 不新增只在前端伪装可用、但服务端未落地的实体能力
- 不允许 `db/*` 中的写操作静默成功
- 不允许在没有 Prisma 模型和本地 API 的情况下开启对应 UI 写入口
- 任何新能力都必须同步更新文档与能力边界清单

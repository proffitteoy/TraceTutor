# TraceTutor 架构设计

## 1. 当前架构

TraceTutor 采用四个运行边界：

```text
Iris 前端
  ↓ HTTP
API + 本地 Agent Runtime
  ↓ ToolExecutionPort
  ├─ 内部 HTTP → SQLite 用户状态服务 → SQLite 文件
  └─ PgSQL 题目资产适配器 → PostgreSQL

API + 本地 Agent Runtime
  ↓ OpenAI-compatible API
模型服务
```

这里的“本地 Agent”指路由、Workflow、工具调度、状态机、校验与响应组装全部运行在本地 API 进程；模型推理通过可配置 API 接入，不把 Agent 控制权交给模型服务。

## 2. 各层职责

| 层 | 负责 | 不负责 |
|:---|:---|:---|
| Iris | 用户输入、动作、卡片渲染、会话身份 | 数据库查询、判题、掌握度规则 |
| API | HTTP、鉴权、契约、错误、健康检查 | 自由生成教学内容 |
| LocalAgentRuntime | QueryPlan、Workflow、工具调度、模型调用、引用校验、响应组装 | SQL、数据库连接、正式状态规则 |
| 模型 API | 结构化计划、判定建议、教学内容 | 工具权限、持久化、可信 ID |
| PgSQL | 稳定题目、解析、知识点、方法、相似关系 | 用户状态 |
| SQLite | 作答事实、掌握状态、复习调度、运行日志 | 完整题目资产 |

## 3. 主调用路径

```text
LearningRequest
  ↓
本地 Agent 调模型生成 QueryPlan
  ↓
本地 Schema 与白名单校验
  ↓
ToolExecutionPort 读取状态 / 题目资产
  ↓
压缩工具结果
  ↓
必要时判题并写作答事实
  ↓
规则层校验并应用 pending state delta
  ↓
模型组织教学卡片
  ↓
本地检查所有 ID 引用
  ↓
LearningResponse
```

模型不能跳过任何本地校验阶段。

## 4. 两个核心流程

### 新题讲解

```text
用户输入题目
  ↓
QueryPlan
  ↓
可选读取已知题目资产
  ↓
模型生成可检查的解题步骤
  ↓
返回 solution / method cards
```

新题尚未拥有可信 `question_id` 时，响应不得伪造题目卡 ID。若要沉淀，必须先通过 `asset.create_draft_question` 创建 draft，成功后才能引用其 ID。

### 复习与作答

```text
查询用户快照 / 错题 / 到期复习
  ↓
召回 active 题目
  ↓
组织旧题 review / 同知识点题 / 方法迁移
  ↓
Iris 提交 action + answer
  ↓
读取题目详情与解题步骤
  ↓
判题
  ↓
记录 attempt
  ↓
验证并应用状态变化
```

数据库不可用时仍可讲解用户当前输入，但不能声称读取了历史或保存了状态。

## 5. 题目资产边界

PgSQL 存：

- 题干、标准答案、解析；
- 知识点、方法、难度、题型；
- 知识点相似、方法相似、结构相似、解题路径相似；
- 来源和质量状态。

质量状态至少区分：

```text
draft / imported / staging / active / rejected
```

只有 `active` 可进入正式召回。AI 临时生成题默认是 draft。

## 6. 用户状态边界

SQLite 存：

- session、attempt、review event；
- 掌握状态与事件；
- 错因模式；
- review schedule；
- context summary；
- workflow 与 tool 日志；
- pending state delta。

SQLite 只保存 `question_id` 等资产引用，不复制整题内容，也不与 PgSQL 建跨库外键。

## 7. 状态引擎

状态流转由数据库规则层负责，而不是模型自由生成：

```text
unseen
  ↓
attempted
  ↓
understood / weak
  ↓
reviewing
  ↓
stable
```

状态变化必须有：

- 真实题目 ID；
- attempt 或 review event；
- 判题结果；
- 对应知识点或方法标签；
- 合法变化范围；
- 幂等事件 ID。

## 8. 相似度引擎

相似不能只用一个分数：

- knowledge；
- method；
- structure；
- solution_path。

Agent 的 QueryPlan 必须明确需要哪种相似，API 工具只接受枚举维度。

## 9. 安全边界

- 不提供 `execute_sql`。
- 所有模型输出都经过本地 Schema。
- 所有工具参数都由本地物化并再次校验。
- 所有题目 ID 都做来源检查。
- 模型 API Key 只放服务端环境变量。
- Iris 只配置公开 API URL。
- 生产工具路由必须使用 Bearer Token。

## 10. 当前完成度

已经完成：

- Iris；
- Fastify API；
- 本地 Agent Runtime；
- OpenAI-compatible 模型客户端；
- QueryPlan / StateDelta / LearningResponse 契约；
- 工具白名单和数据库端口；
- SQLite 6 个迁移和用户状态引擎；
- `HttpSQLiteToolExecutionPort` 及 7 个状态/日志能力；
- SQLite 内部 Bearer 鉴权、幂等写回和就绪检查；
- JSONL 初始化、AI 标签提议、用户题 `draft` 沉淀与人工复核处理器；
- PgSQL 协作者可实现的 `QuestionIngestionPort` 高层契约；
- 本地测试与构建入口。

尚未完成：

- 在目标 PostgreSQL 上执行迁移并导入批准的初始化题；
- 携带目标数据库与模型 API 的端到端联调。

因此仅配置 SQLite 时 API 仍返回 `503`；同时配置并连通 PostgreSQL 与 SQLite 后，15 个工具和题目摄取端口才完整就绪。

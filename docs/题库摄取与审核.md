# 题库摄取与审核

本文定义两条题目沉淀链路：

1. 运维人员用 UTF-8 JSONL 初始化数百道题；
2. 用户在 `new_question` 模式下提问后，系统自动生成待审核题目草稿。

PgSQL 适配器已实现 JSONL 校验、标准化哈希、模型自动标注、用户题沉淀、人工复核、事务写入和 active 质量约束，不提供内存或文件假落库。

## 1. 两条处理链路

```text
初始化 JSONL
  → CLI 分片上传
  → Schema 校验
  → 读取 PgSQL 候选标签字典
  → 模型提议知识点、方法、结构和复核提示
  → code 映射为 PgSQL UUID
  → QuestionIngestionPort 原子写 staging + imported + pending review
```

```text
用户 new_question
  → LocalAgentRuntime 完成讲解
  → 读取候选标签字典
  → 模型整理题干、答案、解析步骤和标签
  → QuestionIngestionPort 原子写 draft + pending review
  → LearningResponse.meta.question_deposit 返回真实写入状态
```

沉淀失败不会中断当前讲题，但响应会返回 `question_deposit.status = failed` 和原因。只有 PgSQL 端口返回真实 ID 时，响应才包含 `question_id` 和 `review_item_id`。

## 2. JSONL 契约

运行时 Schema 位于 `apps/api/src/ingestion/contracts.ts`，示例位于 `db/pgsql/examples/higher-math-limit.sample.jsonl`。

每行必须满足：

- `schema_version = "1.0"`；
- 由维护者提供 `external_id`、来源和学科代码；
- 难度为 1～5；
- 恰好一个主答案；
- 恰好一个主解析，解析必须有正文或至少一个步骤；
- 至少一个知识点和一个方法；
- 初始 `status` 只能是 `imported`；
- 中文数学表达使用 Markdown + LaTeX。

人工维护的是标签 `code`。PgSQL 的 `question_id`、`knowledge_point_id` 和 `method_id` 均由数据库生成，JSONL 不接受人工 UUID。

## 3. AI 标注边界

模型只做提议，不做审核：

- 知识点和方法分别标注；
- 只能返回 `QuestionIngestionPort.loadTaggingContext` 给出的候选 `code`；
- AI 置信度会被限制为小于 1；
- 维护者已有标签保留，AI 建议以独立来源写入；
- 字典中不存在的 `code` 进入 `unresolvedKnowledgeCodes` 或 `unresolvedMethodCodes`，不能伪造 UUID；
- 模型不能把题目改为 `active`。

初始化题目的答案和解析以 JSONL 为准，AI 不改写数学内容。用户题由模型结合已经校验的教学输出整理答案和解析，但仍只能写 `draft`。

## 4. 初始化工具

先启动已经接入 `QuestionIngestionPort` 的 API，然后在 `apps/api` 执行：

```powershell
npm run questions:import -- `
  --file ..\..\db\pgsql\examples\higher-math-limit.sample.jsonl `
  --batch-name "高数极限首批题库"
```

可选参数：

- `--api-url`：默认 `http://127.0.0.1:4100`；
- `--chunk-size`：1～50，默认 20；
- `--batch-key`：显式幂等键；缺省时由文件路径和内容生成；
- `TRACE_TUTOR_TOOL_TOKEN`：生产环境的内部 Bearer Token。

CLI 保留原始行号和文本，逐分片调用 `POST /internal/question-ingestion/import-chunk`。同一个 `batch_key + line_number` 必须由 PgSQL 适配器幂等处理；`canonical_hash` 冲突必须记为 `duplicate`，不能再生成一份题目。

## 5. 人工复核接口

```text
GET  /internal/question-ingestion/review-queue
POST /internal/question-ingestion/reviews/:reviewItemId
```

复核决策为：

- `approve`：题目满足 active 最低字段后，事务性写审核日志并切换为 `active`；
- `reject`：写审核日志并切换为 `rejected`；
- `needs_fix`：保留 `draft/imported`，进入待修正队列。

复核请求可修正题干、题型、难度、答案、解析、知识点 UUID 和方法 UUID。PgSQL 适配器在批准事务中必须再次检查：

- 有且仅有一个主答案和主解析；
- 至少一个主知识点和主方法；
- 所有标签 UUID 存在且处于可用状态；
- 来源、质量状态和审核人完整；
- imported/draft 不能绕过审核直接 active。

## 6. PgSQL 接入清单

实现 `apps/api/src/ports.ts` 的 `QuestionIngestionPort`：

- `loadTaggingContext`：按题干、学科和已有 code 返回有限候选字典；
- `beginImportBatch`：按 `batchKey` 幂等创建或恢复批次；
- `recordImportItem`：原子维护 staging、题目资产和 pending review，并处理 hash/行号重复；
- `finishImportBatch`：基于已落库条目统计并完成批次；
- `writeUserQuestionDraft`：原子写 draft、来源会话和 pending review；
- `listReviewQueue`：提供游标分页；
- `applyReview`：带并发检查地写审核日志和题目状态。

该端口是高层业务接口，不得向 Agent 暴露连接、ORM、repository 或 SQL。生产入口已将同一个 `QuestionIngestionService` 装配到本地 Runtime 与 HTTP 应用；未配置 PgSQL 时导入与复核接口返回 `503 DEPENDENCY_UNAVAILABLE`。

## 7. 当前验证边界

当前可以验证：

- JSONL 必填字段、主答案和主解析约束；
- AI 标签候选限制和 code → UUID 映射；
- 未知标签隔离；
- imported/draft 生命周期；
- 批量失败行记录、分片完成、用户题自动沉淀和人工决策转交。

当前不能验证：

- PgSQL 事务、唯一约束、迁移和备份；
- 数百题真实写库吞吐与模型限流；
- 审核 UI；
- active 题进入 8 个 `asset.*` 召回工具的端到端路径。
